# R&D 특구 유사 과제 검색 프로토타입 — 디자인 브리프

Claude Design(캔버스 목업)에 입력하기 위한 요약 문서. 스펙 문서(`00_docs/superpowers/specs/2026-08-21-rnd-similar-task-search-design.md`,
개정 2, 사용자 승인 완료)와 `PROJECT_PLAN.md`를 기준으로 정리했다.

## 0. 한 줄 소개 및 산출물 형태

신규 R&D 과제를 기획하는 사람이, 준비 중인 주제를 입력하면 비슷한 기존 과제가 몇 건 있고 어떤 기관·
연구자가 수행했는지 확인하는 도구. **1단계 산출물은 Jupyter 노트북**(코드 셀 출력이 곧 화면)이며, 별도
웹 UI 프레임워크나 브랜드 디자인 시스템은 없다 — 즉 지금 이 브리프는 "코드로 이미 정해진 요소들을 어떤
모양으로 배치·스타일링할지"를 위한 입력이며, 새 인터랙션이나 새 화면을 발명하는 브리프가 아니다.

사용자는 한 종류: **주제를 입력하고 결과를 직접 조작·탐색하는 사람**. 발표를 옆에서 지켜보는 관객은
별도 사용자로 다루지 않는다(이 사람이 조작하는 걸 보는 입장으로 취급).

## 1. 화면 1 — 유사 과제 검색 (핵심 화면)

### 입력 영역
- **Text 입력창**: placeholder "준비 중인 과제의 주제를 입력하세요", label "과제 주제:"
- **랭킹 기준 Dropdown**: label "랭킹 기준:", 옵션 3개 — `최고 유사도`(기본값) / `유사 과제 건수` / `합산 점수`
- **검색 버튼**: label "검색", 강조 스타일(primary)
- 이 세 위젯은 한 줄(가로 배치)에 나란히 놓인다

### 출력 영역 — 정상 결과(임계값 이상 매칭 있음)
1. 안내 텍스트: "내 주제가 속한 것으로 추정되는 클러스터 번호: N"
2. 안내 텍스트: "유사 과제 건수: N건"
3. 안내 텍스트: "수행 기관: A, B, C, ..." (중복 제거된 기관 목록)
4. **유사 과제 표** (Top-N, 기본 5행): 컬럼 = `과제명 / 주관기관명 / 연도 / 유사도 / 클러스터`
5. **연구자 추천 표** (Top-N, 기본 5행): 컬럼 = `연구책임자명 / 주관기관명 / 특구지역 / 대표 유사 과제명 / 유사도 / 과제수`
   - 연구책임자명 중 동명이인(이름+기관까지 같은 11쌍)은 `홍길동(1234)` 형태로 연구자번호 뒷 4자리 표기
   - 위 랭킹 드롭다운을 바꾸면 이 표만 재정렬(검색 버튼을 다시 누르지 않아도 됨)

### 출력 영역 — 0건(임계값 미달) 결과
- 유사 과제 표 자리에 고정 문구: "정확히 일치하는 유사 과제를 찾지 못했습니다. 아래는 유사도가 가장
  높았던 3건입니다(참고용)." + 참고용 상위 3건
- 연구자 추천 표 자리에 고정 문구: "참고용 — 임계값 미달: 유사도가 가장 높은 연구자 3명입니다." +
  연구자 3명(항상 정확히 3명, 건수 아님)
- 두 "참고용" 상태는 시각적으로 구분되어야 함(예: 옅은 배경색, 경고 아이콘, 회색 처리 등 — 정상 결과와
  섞여 보이면 발표 중 오해 소지)

### 출력 영역 — 빈 입력 / 극단적 0건
- 입력창이 비었거나 공백만 있으면: "검색어를 입력해주세요." (표 자체를 그리지 않음)
- 특구 소속 과제 데이터 자체가 0건인 극단적 경우: "특구 소속 기관이 수행한 과제 데이터가 없습니다."
- 두 경우 모두 파이썬 에러 화면(빨간 트레이스백)이 노출되면 안 됨 — 실패 상태도 항상 위 문구 중 하나로
  귀결되어야 함

## 2. 화면 2 — 전체 클러스터 지도 (보조 화면)

- **Plotly 산점도**: x/y = TruncatedSVD 2차원 좌표
- **색상**: KMeans 클러스터(현재 6개 클러스터로 확정)별로 구분
- **hover 텍스트**: 과제명 / 기관명 / 특구지역 / 클러스터 번호
- **하이라이트 마커**: 화면1에 입력한 주제의 투영 위치를 별(★) 모양 등 구분되는 마커로 표시하고, 마커
  옆에 "내 주제 (클러스터 N)" 텍스트 라벨을 붙인다 — 화면1에서 본 클러스터 번호와 화면2의 마커 라벨의
  번호가 항상 같아야 한다(핵심 완료조건)
- 범례에 클러스터 번호가 그대로 노출되어도 무방(공개 데이터 기반이라 클러스터 번호 자체는 민감하지 않음)

## 3. 화면 간 관계

- 화면1과 화면2는 **같은 노트북의 순차적인 셀 출력**이며, 별도 페이지 전환/네비게이션이 없다. 위→아래로
  스크롤하면 화면1 다음에 화면2가 나오는 구조
- 두 화면을 잇는 유일한 접점은 "클러스터 번호"다 — 화면1의 표·안내 텍스트에 나온 번호가 화면2 산점도의
  같은 색 점 그룹과 맞아떨어져야 한다는 것이 이 도구의 핵심 신뢰 포인트

## 4. 데이터 성격 / 민감도

- 연구자 실명과 8자리 연구자번호가 포함된 데이터를 다룬다. 화면에는 실명이 그대로 노출되지만(기능상
  불가피), 연구자번호는 동명이인 구분이 필요한 최소한의 경우(11쌍)에만 뒷 4자리를 노출한다
- 디자인 톤: 공공데이터 기반의 사실적/실무적 도구 — 마케팅성 화려함보다는 "이 결과가 왜 나왔는지 설명
  가능함"을 신뢰감 있게 전달하는 방향이 스펙의 전체 기조와 맞는다(TF-IDF 코사인 유사도를 택한 이유가
  "결과가 결정적이라 설명 가능"이었음)

## 5. 브랜드/스타일 가이드

없음 — 확정된 컬러 팔레트, 폰트, 로고 등이 없는 개인 프로토타입이다. Claude Design에서 자유롭게 제안
가능하나, 아래는 지켜야 하는 제약:
- 위젯 개수는 정확히 3개(Text, Dropdown, Button) — 화면1에 그 이상 입력 요소를 추가하지 않는다
- 화면은 정확히 2개(화면1 핵심, 화면2 보조) — 화면3을 새로 만들지 않는다
  - (2026-08-30 갱신: 이 제약은 A.1 브리프 기준. 이후 A.2에서 03 에고그래프, A.3에서 04 지역 기술편중이 추가돼 현재 4섹션 — HANDOFF.md §10 참고)
- "참고용" 상태와 정상 상태가 시각적으로 명확히 구분되어야 한다(위 1절 참고)
