Claude Design(캔버스)에 입력해 발표용 보고서 문서로 시각화하기 위한 계획서. FastAPI 백엔드 + 정적
웹 프론트로 구현하는 R&D 유사 과제 검색 웹앱의 전체 흐름을 다룬다. 근거 문서:
`00_docs/superpowers/specs/2026-08-21-rnd-similar-task-search-design.md`(개정 2, 승인 완료),
`PROJECT_PLAN.md`, `DESIGN_LOG.md`, `HANDOFF.md`.

## 1. 한 줄 소개

신규 R&D 과제를 기획하는 사람이 준비 중인 주제를 입력하면, 이미 존재하는 비슷한 과제가 몇 건이고
어떤 기관·연구자가 수행했는지 그 자리에서 확인할 수 있는 검색 도구.

## 2. 배경

공공데이터포털에서 연구개발특구진흥재단이 제공하는 데이터를 조사했을 때, 개별 "과제" 단위의
분야·키워드 정보를 가진 데이터셋은 없었다(기업 목록, 지역 정보, 지구별 집계 통계뿐). 그래서
한국연구재단이 제공하는 `이알앤디_과제정보`(과제명 포함, 11,788건)를 결합해, "R&D 특구 소속 기관이
수행한 과제"만 추출해 활용하는 방향으로 설계했다.

처음 구상은 LLM·GNN 기반의 과제 유사·중복성 자동 분류 및 TRL 연계 사업화 예측 모델이었으나, 하루
안에 완성 가능한 범위로 좁혀 "국가R&D 클러스터 기반 유사과제 조회 및 연구자 추천 서비스"로
재정의했다.

## 3. 페르소나 & 핵심 니즈

**신규 과제를 기획하는 사람** — 자신이 준비 중인 주제와 비슷한 과제가 이미 있는지, 있다면 몇 건이고
어떤 기관·연구자가 수행했는지 확인하고 싶다.

사용자는 한 종류(주제를 입력하고 결과를 직접 조작·탐색하는 사람)로 한정한다. 

## 4. 접근 방법 선택 — TF-IDF 코사인 유사도

| 비교한 방법 | 채택 여부 | 이유 |
|---|---|---|
| **TF-IDF 코사인 유사도 검색** | 채택 | 화면2의 클러스터 지도(TruncatedSVD+KMeans)와 벡터화를 하나의 파이프라인으로 공유 가능. scikit-learn 하나로 벡터화·유사도·차원축소·군집화 전부 해결. 결과가 결정적이라 "왜 이 과제가 검색됐는지" 설명 가능 |
| 키워드/카테고리 규칙 기반 필터 | 기각 | 유사도 개념 자체가 없어 "비슷한 과제 몇 건"에 답 불가. 표현이 다르면 있어도 0건으로 나와 신뢰를 깎아먹을 위험 |
| 외부 LLM API 의미 판단 | 기각 | 과제 11,788건 전체를 프롬프트에 넣을 수 없어 결국 TF-IDF로 1차 필터링해야 하는 하이브리드가 되어 단독으로 성립 안 함. API 키·네트워크·응답지연·비결정성이 하루 일정과 맞지 않음 |

**알려진 한계**: 동의어/다른 표현(예: "인공지능" vs "AI")을 쓴 과제는 표면적 단어가 겹치지 않아
유사 과제로 잡히지 않을 수 있음. 임계값 튜닝이나 간단한 동의어 정규화 수준에서만 완화하고, 별도
인프라(LLM 등)는 새로 두지 않는다.

**보강(3단계, 2026-08-22) 및 대규모 검증(2026-08-31)**: 위 한계를 완화하기 위해 화면1 검색에 로컬
문장 임베딩(`jhgan/ko-sroberta-multitask`)을 TF-IDF와 병행 계산해 큰 값을 쓰는 방식을 추가했다
(화면2 클러스터링은 TF-IDF만 그대로 사용, 완료조건 2 불변). 처음에는 예시 문장 3개로만 효과를
확인했으나(§11 확정 파라미터 참고), 표본이 너무 작다는 지적(모의 심사 리뷰 §4번 이슈)에 따라
매칭 코퍼스 **1,680건 전체를 self-search 방식으로 재검증**했다(`_verify_embedding_rescue.py`):
- 1,680건 중 **545건(32.4%)이 TF-IDF만으로는 유사 과제 0건**이었고, 그중 **376건(69.0%, 전체의
  22.4%)이 임베딩 결합으로 구제**됨(TF-IDF가 완전히 놓친 것을 임베딩이 찾아냄)
- 건수 median 1.0→4.0, mean 1.84→8.83으로 증가
- 구제된 케이스의 임베딩 최고유사도 median 0.677(최소 0.600, 최대 0.867) — `EMBEDDING_SIMILARITY_THRESHOLD
  =0.6`이 실제로 의미 있는 지점에서 작동함을 1,680건 규모로 확인
- 임계값 근거 보강: 전체 임베딩 쌍(1,680×1,680=282만 쌍, 대각선 제외) 중 0.6 이상인 쌍은 0.44%
  (12,384쌍)뿐, p99.9=0.677 — "무관한 쌍은 대부분 0.6을 못 넘는다"는 주장을 예시 3개가 아니라
  282만 쌍으로 뒷받침

**이 수치의 한계(과대해석 주의)**: 위는 "과제명 대 과제명" self-search 결과라 실제 사용자가 자유
문장으로 입력하는 것과 문체가 다르다. "이 메커니즘이 실제로 작동한다"는 증거로는 유효하지만,
"실사용 시 22.4%가 혜택을 본다"는 식으로 확대해석하면 안 된다.

## 5. 데이터 개요 및 파이프라인

데이터 위치: `01_data/` (cp949 인코딩, utf-8로 열면 깨짐, `.gitignore`로 제외)

| 데이터셋 | 제공처 | 건수 |
|---|---|---|
| 특구입주기업현황.csv | 연구개발특구진흥재단 | 6,359건 (고유 기관 6,258개) |
| 이알앤디_과제정보.csv | 한국연구재단 | 11,788건 |

```
[1] 데이터 수집 (CSV 2종, 수동 다운로드)
      │
[1.5] 보안과제 제외 — 보안과제여부 == 'Y' 5건 제거 → 11,783건
      │
[2] 기관명 정규화(.str.strip()만) & 정확 매칭 조인
      → 27개 기관 / 1,680건 추출
      │
[3] 과제명 TF-IDF 벡터화 (단순 토큰화, 형태소 분석기 미사용)
      │
      ├─[4a] 코사인 유사도 검색 → 건수/기관/Top-N/클러스터 번호
      ├─[4b] TruncatedSVD 2D 축소 + KMeans 클러스터링(6개 클러스터)
      └─[4c] 연구자번호 기준 집계 → 랭킹 드롭다운 3종으로 정렬
      │
[5] 화면1(검색 결과 + 연구자 추천) / 화면2(전체 클러스터 지도)
```

**정규화 방식 주의**: 법인 접미사 제거를 시도했으나 27개/1,680건이 아닌 30개/2,008건으로 어긋남을
실측으로 확인 — 매칭된 27개 기관이 전부 대학·출연연·진흥원이라 원래 접미사가 없고, 제거 로직이
무관한 이름을 우연히 겹치게 만들었기 때문. `.str.strip()`만 적용하는 것으로 확정.

## 7. 화면 설계 상세

### 화면 1 — 유사 과제 검색 (핵심 화면)

**입력 영역** (한 줄, 가로 배치, 위젯 정확히 3개)
- Text 입력창 — placeholder "준비 중인 과제의 주제를 입력하세요", label "과제 주제:"
- 랭킹 기준 Dropdown — label "랭킹 기준:", 옵션: `최고 유사도`(기본값) / `유사 과제 건수` / `합산 점수`
- 검색 버튼 — label "검색", primary 스타일

**출력 영역 — 정상 결과**
1. "내 주제가 속한 것으로 추정되는 클러스터 번호: N"
2. "유사 과제 건수: N건"
3. "수행 기관: A, B, C, ..." (중복 제거)
4. 유사 과제 표 (Top-5): 과제명 / 주관기관명 / 연도 / 유사도 / 클러스터
5. 연구자 추천 표 (Top-5): 연구책임자명 / 주관기관명 / 특구지역 / 대표 유사 과제명 / 유사도 / 과제수
   - 동명이인 11쌍만 `홍길동(1234)` 형태로 연구자번호 뒷 4자리 표기
   - 랭킹 드롭다운 변경 시 검색 버튼 재클릭 없이 이 표만 재정렬

**출력 영역 — 0건(임계값 미달)**
- 유사 과제 표 자리: "정확히 일치하는 유사 과제를 찾지 못했습니다. 아래는 유사도가 가장 높았던
  3건입니다(참고용)." + 참고용 상위 3건
- 연구자 추천 표 자리: "참고용 — 임계값 미달: 유사도가 가장 높은 연구자 3명입니다." + 항상 정확히
  3명 (건수 아님)
- 두 "참고용" 상태는 정상 결과와 시각적으로 명확히 구분(옅은 배경색·경고 아이콘·회색 처리 등)

**출력 영역 — 빈 입력 / 극단적 0건**
- 빈 값·공백만 입력: "검색어를 입력해주세요." (표를 그리지 않음)
- 특구 소속 과제 데이터 자체가 0건: "특구 소속 기관이 수행한 과제 데이터가 없습니다."
- 두 경우 모두 파이썬 에러(빨간 트레이스백)가 노출되지 않아야 함

### 화면 2 — 전체 클러스터 지도 (보조 화면)

- Plotly 산점도: x/y = TruncatedSVD 2차원 좌표, 색상 = KMeans 클러스터(6개)
- hover 텍스트: 과제명 / 기관명 / 특구지역 / 클러스터 번호
- 하이라이트 마커: 화면1 입력 주제의 투영 위치를 별(★) 모양으로 표시 + "내 주제 (클러스터 N)" 라벨
- **화면1에서 본 클러스터 번호와 화면2 마커 라벨의 번호가 항상 일치**해야 함(핵심 완료조건)

### 화면 간 관계

화면1과 화면2는 순차적으로 배치되며(위→아래 스크롤), 두 화면을 잇는 유일한 접점은 "클러스터
번호"다. 이 번호 일치가 이 도구의 핵심 신뢰 포인트다.

### 데이터 성격 / 민감도

연구자 실명과 8자리 연구자번호를 다룬다. 화면에는 실명이 노출되지만(기능상 불가피), 연구자번호는
동명이인 구분이 필요한 최소한의 경우(11쌍)에만 뒷 4자리를 노출한다. 디자인 톤은 공공데이터 기반의
사실적/실무적 도구 — "결과가 왜 나왔는지 설명 가능함"을 신뢰감 있게 전달하는 방향.

**실명 노출 대응 방침(2026-08-31 확정)**: 연구책임자 성명은 한국연구재단이 이미 공공데이터로 개방한
필드이며, 본 서비스는 NTIS(국가과학기술지식정보서비스)와 동일한 수준으로 노출한다. 다만 NTIS가
회원가입·로그인을 최소한의 접근 문턱으로 두는 것에 맞춰, 배포판에는 이메일만 입력받는 약한 접근
게이트(access log)를 두고, "연구·기획 목적 외 이용을 제한"하는 이용약관을 적용한다. 즉 실명 자체를
마스킹하는 방향이 아니라, **노출 수준을 기존 공공 서비스(NTIS)와 맞추고 목적 제한으로 대응**하는
방향으로 확정했다.

## 8. 시스템 아키텍처

Claude Design에서 받은 UI 목업("UI mockups for design-brief-handoff.zip", `RnD 유사과제 검색.dc.html`)을
실제 기술스택으로 pixel-perfect 재구현하는 작업. 데이터/로직 연결 방식은 가벼운 로직 서버(FastAPI)로
확정.

```
03_webapp/
├── backend/
│   ├── pipeline.py   ← 검색·군집화 알고리즘 구현
│   └── main.py        ← FastAPI, /api/clusters, /api/search
└── frontend/
    ├── index.html / styles.css / app.js   ← 순수 HTML/CSS/바닐라 JS (목업의 디자인시스템 번들 미사용)
    └── fonts/          ← NanumSquare 4종
```

| 구분 | 내용 |
|---|---|
| 입력 | ① CSV 2종(로컬 파일, cp949) ② 화면1 Text 입력창 자유 텍스트 ③ 랭킹 드롭다운 선택값 |
| 처리 | 보안과제 제외 → 기관명 조인 → TF-IDF 벡터화 → 코사인 유사도 / SVD+KMeans / 연구자 집계, FastAPI 서버 프로세스 내 연산 |
| 외부 호출 | 없음 |
| 저장 | 없음 — 요청마다 서버 메모리 내 처리, 별도 DB 없음 |

- `/api/clusters`: 전체 과제 산점도 데이터 (화면2)
- `/api/search`: 주제 텍스트 + 랭킹 기준 → 유사 과제/연구자 추천 결과 (화면1)
- 클러스터에 의미 라벨을 붙이지 않음("클러스터 0" ~ "클러스터 5"로만 표시) — 비지도학습 결과에
  근거 없는 라벨을 붙이면 "기술이전 예측" 기각과 같은 문제(없는 값 발명)가 됨

## 10. 완료 조건 / 성공 기준

| # | 조건 | 확인 방법 |
